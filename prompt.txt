## Tech stack
- Frontend + backend: Next.js 14 (App Router, TypeScript, Tailwind CSS). Use API route handlers as the backend.
- Face recognition service: Python 3.10+ with FastAPI, using DeepFace (Facenet512, 512-d embeddings), rapidfuzz for fuzzy name matching, and networkx for clustering.
- Database: Neo4j (Aura Free or Docker, v5.11+) with a vector index. Use neo4j-driver in Next.js and the neo4j Python driver in the Python service.
- Next.js calls the Python service over HTTP (e.g. http://localhost:8000).

## Background: how ASTR works
1. Subscriber photos come from telecom operators (TSPs).
2. Faces are detected and analysed into a "faceprint" (embedding).
3. Similar-looking faces are grouped together.
4. Textual KYC details (name, DOB, address, bank account, ID proof) are compared with fuzzy string matching to group approximately similar names.
5. Flag cases where the same face holds SIMs under multiple names, DOBs, bank accounts or address proofs, or where more than 8 SIMs are held in one person's name.

# PHASE 1: CORE APP (build this now)

## Graph model (Neo4j)
- (:Subscriber {id, name, dob, address, kyc_id, bank_account})
- (:Face {id, embedding, image_path})
- (:SIM {number, activated_on})
- (:TSP {name})
- (:Identity {id}) represents a cluster of faces judged to be the same person
- (:Review {decision, reviewer, timestamp, note})
- Relationships: (Subscriber)-[:HAS_FACE]->(Face), (Subscriber)-[:OWNS]->(SIM), (SIM)-[:ISSUED_BY]->(TSP), (Face)-[:SIMILAR_TO {score}]->(Face), (Face)-[:BELONGS_TO]->(Identity), (Identity)-[:REVIEWED_AS]->(Review)
- Vector index face_idx on Face.embedding (512 dims, cosine). Add uniqueness constraints on ids.

## Synthetic data generator (script)
- Download faces with scikit-learn: fetch_lfw_people(min_faces_per_person=3, color=True) and save them to /faces/<person_name>/<n>.jpg.
- Use Faker (locale en_IN) to generate about 100 subscribers, each with name, DOB, address, KYC id, bank account, and 1-3 SIMs across 3 TSPs. Assign each subscriber one LFW person as their face (one photo).
- Plant fraud cases using DIFFERENT photos of the SAME LFW person (different angle and lighting), never the same image file:
  (a) 5-8 people, each registered 2-3 times as separate subscribers with slightly altered names (e.g. "Rajesh Kumar", "Rajesh Kumr", "Rakesh Kumar"), different DOBs and different SIMs;
  (b) one subscriber holding 9+ SIMs;
  (c) one face sharing a bank account with a differently named subscriber.
- Save a ground_truth.json listing the planted fraud clusters so detection precision and recall can be measured and shown in the demo.
- Load everything into Neo4j (Subscriber, Face, SIM, TSP nodes and relationships), then call the face service to embed, cluster and flag.

## Python face service (FastAPI)
- POST /embed: accepts an image, returns a 512-d embedding.
- POST /ingest: embeds all images in a folder and stores Face nodes in Neo4j.
- POST /cluster: for each face, query the vector index (k=10), create SIMILAR_TO edges where cosine score > 0.8 (configurable), run connected components with networkx, and write Identity nodes and BELONGS_TO edges.
- POST /fuzzy-check: for each Identity cluster, compare subscriber names with rapidfuzz token_sort_ratio (> 85 is suspicious) and compare DOB, address and bank account. Return a risk score per cluster.
- POST /search: upload a photo and return the top 5 most similar faces with scores and their subscribers.
- GET /evaluate: compare detected clusters with ground_truth.json and return precision and recall.

## Key Cypher queries
- Same face, multiple identities: MATCH (i:Identity)<-[:BELONGS_TO]-(:Face)<-[:HAS_FACE]-(s:Subscriber) WITH i, collect(DISTINCT s.name) AS names, count(DISTINCT s) AS n WHERE n > 1 RETURN i, names, n
- More than 8 SIMs: MATCH (s:Subscriber)-[:OWNS]->(m:SIM) WITH s, count(m) AS sims WHERE sims > 8 RETURN s, sims
- Vector search: CALL db.index.vector.queryNodes('face_idx', 5, $embedding) YIELD node, score
